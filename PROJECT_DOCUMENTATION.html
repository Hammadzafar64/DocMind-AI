Official Technical Report & Architecture Manual

DocMind-AI

AI-Powered Document Intelligence, Semantic RAG Retrieval & Smart Summarization

1. Executive Summary & Purpose

DocMind-AI is an intelligent document interaction platform developed to eliminate information overload when analyzing dense documents (PDFs, Word documents, research papers, legal contracts, and reports).

Unlike conventional chatbots that hallucinate or leak confidential documents, DocMind-AI leverages Retrieval-Augmented Generation (RAG). Documents are processed locally into semantic vector chunks. Queries retrieve the exact matching context using Cosine Similarity, allowing the AI to deliver answers grounded strictly in the source material with verifiable citations.

3. System Architecture & RAG Workflow

The 6-Phase RAG Pipeline:
  1. Document Ingestion: Multer receives PDF/DOCX files up to 25MB and writes them to disk.
  2. Text Extraction: pdf-parse extracts text from PDF byte streams; mammoth extracts text from Word XML nodes.
  3. Chunking with Overlap: Slices text into 800–1000 character windows with 100-character overlap to preserve sentence boundaries.
  4. Vectorization: Mathematical representation of chunks indexed in VectorStore.
  5. Cosine Similarity Retrieval: When user queries, DocMind finds top-K matching paragraphs.
  6. LLM Generation: Combines system instructions + retrieved context + user prompt to generate answers with source citations.

6. Common Viva & Supervisor Questions

Q: Why use RAG instead of fine-tuning?
Fine-tuning is slow, expensive, and requires full model retraining when documents update. RAG indexes documents dynamically in seconds and grounds answers strictly in real context, preventing hallucinations.
Q: How are third-party API keys secured?
API keys (Google Gemini) are strictly stored in .env on the server. The client never sees raw keys; all LLM calls are server-side proxies, and settings endpoints return keys masked as ********.
Q: What is the difference between 401 and 403 HTTP codes?
401 Unauthorized means the request lacks valid authentication credentials ("Who are you?"). 403 Forbidden means the identity is valid, but lacks administrative permission ("You are not allowed").
